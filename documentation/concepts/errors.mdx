Every failure is an `SdkError`. It carries four things, and each answers a different question:

| Field | Question it answers | Audience |
|-------|--------------------|----------|
| `code()` | Which failure is this? | your `match` |
| `message()` | What happened? | safe to show a player |
| `hint()` | What do I do about it? | you, in the logs |
| `context()` | Which values were involved? | you, debugging |

`Display` renders all four, so a single log line is usually enough:

```
ticket_invalid: The cached ticket was issued for a different title.
  — Confirm the public key compiled into your build matches the one in the
    Arcane portal. (expected=pk_abc, ticket_gid=pk_xyz)
```

```rust
match ArcaneClient::init(PUBLIC_KEY) {
    Ok(client) => start_game(client),
    Err(err) => {
        eprintln!("{err}");                    // full detail for your logs
        show_player(err.message());            // just the human sentence
        if err.is_retryable() { offer_retry(); }
    }
}
```

`is_retryable()` is `true` when retrying the same call could succeed once something outside your code changes — the network returns, Arcane opens, the player signs in. It is `false` when nothing will change without a code, account, or machine change.

## Error codes

| Code | Problem | What to do | Retryable |
|------|---------|------------|-----------|
| `invalid_public_key` | Empty, over 256 bytes, or a character outside `A–Z a–z 0–9 _ - .` | Check the value you compiled in — the context names the bad character and its index | no |
| `invalid_argument` | An argument other than the public key is empty, oversized, or has a forbidden character — today, an [achievement](/concepts/achievements) key over 64 bytes or outside `a–z 0–9 _ - .` (keys are lowercase) | Check the key against the Arcane portal. Raised before any network call, or when Arcane rejects the key | no |
| `ticket_missing` | No ticket cached for the signed-in account, or an empty ticket while DRM is on | Open Arcane desktop once while online. `init` normally refreshes this for you | yes |
| `ticket_expired` | JWT past `exp` (beyond ±5 min skew) | `init` normally refreshes this for you; otherwise reconnect online via Arcane | yes |
| `ticket_invalid` | Bad JWT, missing/unreadable JWKS, unknown `kid`, wrong title, `own=false`, corrupt file | Refresh via Arcane. If `expected` ≠ `ticket_gid` in the context, your public key is wrong | no |
| `device_mismatch` | Ticket bound to another machine | Refresh ownership on this machine while online. Context shows both fingerprints | no |
| `clock_rollback` | System clock earlier than the ticket or the last-seen time | Enable automatic date & time, then retry | no |
| `not_owned` | Cloud confirmed this account does not own the title | Send the player to the Arcane Store or marketplace | no |
| `network_required` | No usable offline ticket and the refresh needs the network | Connect to the internet, open Arcane, retry | yes |
| `not_authenticated` | Nobody is signed in — either Arcane says so, or `session.json` records a signed-out state | Sign in to the Arcane desktop app, then retry | yes |
| `arcane_unavailable` | Could not reach or launch the Arcane desktop app | Install or launch Arcane Powered. Context shows the port and how long the SDK waited | yes |
| `feature_unavailable` | The Arcane desktop app does not know the route the SDK asked for — it predates the feature | Update the Arcane Powered desktop app. Never returned by `init`: an older desktop only degrades the [play session](/concepts/session) to `Pending`, and makes [achievements](/concepts/achievements) return this code | no |
| `unknown_achievement` | The desktop app knows the route, but the title defines no achievement with that key | Check the key against the Arcane portal, and that the achievement is published. The context carries `achievement_key` | no |
| `ambiguous_session` | Several accounts hold a ticket for this title and Arcane has not recorded which is signed in | Open Arcane desktop once so it records the session. Needs a build that writes `session.json` | no |
| `not_initialized` | A C ABI getter was called before `arcane_sdk_init` | Call `arcane_sdk_init` once at launch first | no |
| `internal` | Filesystem / path failure | Check permissions on the Arcane DRM directory — context names the path | no |

## By function

### `ArcaneClient::init` / `arcane_sdk_init`

Can return any code in the table except `not_initialized`.

If the cached `drm_enabled` flag is `false`, init succeeds with `DrmDisabled` and never reaches the ticket codes. When the offline check returns `ticket_missing` or `ticket_expired`, init contacts Arcane desktop (and may open it), which adds `not_owned`, `network_required`, `not_authenticated` and `arcane_unavailable` to the possible outcomes.

The play session opened by `init` never surfaces an error. When the desktop app is missing, older than the session routes (`feature_unavailable`), or simply unhappy, tracking stays `Pending` and the SDK retries every 60 seconds. Read `client.session().tracking` if you want to know.

### `ArcaneClient::refresh` / `arcane_sdk_refresh`

Same codes as init, minus `invalid_public_key` (the key was already validated). Always contacts the desktop app, so it never returns a purely offline result. On failure the client keeps its previous state.

Under `ARCANE_OFFLINE_ONLY` it returns `network_required` immediately.

### `Achievements::list` / `unlock` — `arcane_sdk_achievements_json`, `arcane_sdk_achievement_unlock`

`invalid_argument` (bad key, before any call), `unknown_achievement`, `not_owned`, `not_authenticated`, `network_required` (also under `ARCANE_OFFLINE_ONLY`), `arcane_unavailable`, `feature_unavailable`.

An already-unlocked or `queued` answer is a **success**, not an error — see [Achievements](/concepts/achievements).

`Achievements::is_unlocked` / `arcane_sdk_achievement_is_unlocked` never fail: they read the cache and answer `None` / `-4` when `list` has never succeeded or the key was not in it.

### `ArcaneClient::frame`, `set_graphics`, `session`, `shutdown`

Never fail and never return a `Result`. Before the desktop app acknowledges the session they are simply no-ops that keep counting locally.

### C ABI getters

`not_initialized` before `arcane_sdk_init` succeeds. See the return-code tables below.

## Status vs error

A successful check returns `OwnershipStatus`:

| Value | Meaning |
|-------|---------|
| `Owned` | Valid ticket for this public key, this account, and this device |
| `DrmDisabled` | DRM is off for this title; no ticket required |

Both mean **launch the game**. `is_owned()` distinguishes them if you need to.

## C ABI return values

Two conventions, by function kind.

### Actions — `arcane_sdk_init`, `arcane_sdk_refresh`, `arcane_sdk_set_graphics`, `arcane_sdk_achievement_unlock`

| Return | Meaning |
|--------|---------|
| `0` | Success |
| `1` | Bad argument (null / non-UTF-8 string, or not initialised) |
| `2` | `SdkError` — rendered into `err_buf` as `code: message — hint (context…)` |

`arcane_sdk_frame` and `arcane_sdk_shutdown` return nothing and cannot fail.

### Getters — `arcane_sdk_user_id`, `arcane_sdk_game_id`, `arcane_sdk_public_key`, `arcane_sdk_device_hash`, `arcane_sdk_session_json`, `arcane_sdk_achievements_json`, `arcane_sdk_last_error_json`

| Return | Meaning |
|--------|---------|
| `>= 0` | Bytes written, excluding the NUL terminator |
| `-1` | Not initialised |
| `-2` | Null buffer or zero length |
| `-3` | Buffer too small — the buffer is left as an empty string, never truncated |
| `-4` | Value not available (for example no `game_id` reported yet, or the achievement list could not be fetched — read `arcane_sdk_last_error_json` for why) |

`arcane_sdk_ownership` returns `0` (owned), `1` (DRM disabled) or `-1` (not initialised). `arcane_sdk_ticket_expires_at` and `arcane_sdk_checked_at` return a Unix timestamp or `-1`. `arcane_sdk_achievement_is_unlocked` returns `1`, `0`, `-1` (not initialised), `-2` (null / non-UTF-8 key) or `-4` (nothing cached for that key).

### Structured errors in C

`arcane_sdk_last_error_json` gives the full error for engines that want to render it:

```c
char json[1024];
if (arcane_sdk_last_error_json(json, sizeof(json)) > 0) {
  /* {"code":"not_owned","message":"…","hint":"…","retryable":false,
      "context":{"detail":"…"}} */
}
```

```c
char err[512];
if (arcane_sdk_init(PUBLIC_KEY, err, sizeof(err)) != 0) {
  /* err starts with the code: "not_owned: …", "network_required: …" */
}
```

Per-function notes: [C ABI](/reference/c-abi).
